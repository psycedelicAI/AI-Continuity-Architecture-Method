# Compilation Prompt

You are compiling a Portable Workstate from the synthetic Project Aurora source
material.

The purpose of the compilation is to create a bounded, reviewable, and
transferable context package for a separate receiving AI system.

Do not expand the project beyond the supplied source material.

Do not invent technical specifications, decisions, sources, approvals, or
history.

---

## Source Material

Use only the following Project Aurora source documents:

- `project-aurora-context.md`
- `project-aurora-history.md`
- `project-aurora-decisions.md`

Treat the documents as separate sources.

Do not assume that every statement has the same authority.

---

## Compilation Objective

Compile a Portable Workstate that allows a receiving AI to continue meaningful
work on Project Aurora.

The compiled Workstate must preserve:

- project identity;
- project purpose;
- project intent;
- scope and non-scope;
- current architectural direction;
- operational states;
- human authority;
- canonical decisions;
- proposals;
- historical material;
- superseded material;
- rejected alternatives;
- unverified claims;
- known limitations;
- open questions;
- provenance;
- relevant relationships;
- the intended continuation task.

The Workstate should contain the minimum meaningful context required for the
receiving AI to understand and continue the project.

Do not copy the complete source material automatically.

---

## Required Status Handling

Every important statement must retain its relevant status.

Use the following categories where applicable:

- `Canonical`
- `Inferred`
- `Proposed`
- `Historical`
- `Superseded`
- `Rejected`
- `Unverified`

Do not promote material between categories during compilation.

In particular:

- proposals must remain proposals;
- historical material must remain historical;
- superseded decisions must remain superseded;
- rejected alternatives must remain rejected;
- unverified claims must remain unverified;
- missing values must remain undefined.

---

## Authority Rules

The following authority rules apply:

1. Human-reviewed canonical decisions take precedence over proposals.
2. Current context takes precedence over historical context unless a conflict
   requires explicit review.
3. Superseded decisions must not silently override current decisions.
4. Rejected alternatives must not be presented as available current guidance.
5. Unverified claims must not be presented as established facts.
6. AI-generated interpretations must be labeled as inferences or proposals.
7. Conflicts between source documents must be recorded rather than silently
   resolved.
8. The compiler must not create new authority by wording alone.

---

## Provenance Requirements

For each important compiled element, preserve where possible:

- source document;
- source section;
- decision or claim identifier;
- status;
- authority;
- date;
- version;
- review state;
- relationship to other material.

If exact provenance cannot be preserved, mark the material as incomplete or
unverified.

Do not claim that a source was verified if it was not available.

## Compilation Exclusions

Do not include:

- private PsycedelicAI material;
- real-world project information;
- unsupported technical values;
- invented calculations;
- invented sources;
- fictional approvals not present in the source material;
- claims that the project is deployed;
- claims that the project has been independently validated;
- details irrelevant to the continuation task;
- assumptions presented as decisions.

---

## Continuation Task

The compiled Workstate must instruct the receiving AI to continue Project
Aurora by proposing a structured method for prioritizing essential service
during prolonged constrained operation.

The receiving AI must be instructed to:

- preserve the project intent;
- respect the conceptual scope;
- distinguish canonical context from proposals;
- avoid inventing technical capacity values;
- identify assumptions;
- identify missing information;
- explain risks and trade-offs;
- preserve human authority;
- explain how the proposal could be reviewed;
- record relevant provenance;
- suggest appropriate next actions.

The receiving AI must not be instructed to present the proposal as a confirmed
decision.

---

Before finalizing the Workstate, verify that:

- Project Aurora is clearly identified;
- the project intent is preserved;
- the current architecture is distinguishable from historical proposals;
- canonical decisions are clearly labeled;
- proposed material remains proposed;
- rejected material remains rejected;
- unverified claims remain unverified;
- missing technical values remain undefined;
- human authority is preserved;
- the project remains conceptual;
- open questions are included;
- provenance is present;
- the continuation task is clear;
- no private or real project material has been included.

## Output Requirements

Return only the completed Portable Workstate.

Do not include commentary outside the Workstate.

Do not silently correct source conflicts.

Do not add unsupported information to make the Workstate appear more complete.

If information is missing, preserve the gap explicitly.

If a statement is ambiguous, preserve the ambiguity and label it appropriately.

The final artifact must be suitable for transfer to a separate receiving AI system
for evaluation.
