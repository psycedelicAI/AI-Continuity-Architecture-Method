## Purpose

The purpose of Test Run 04 was to evaluate whether the new Freeze State
Memory Bank could transfer project context to Lumo without requiring separate
vocabulary, repository orientation, project-intent material, or additional
priming.

The test examined whether one consolidated Memory Bank could communicate:

- project identity
- PsycedelicAI collaboration context
- High-Security Facility architecture
- project terminology
- AI Continuity concepts
- Freeze State
- Portable Workstate
- provenance rules
- human authority
- Markdown and document-writing expectations

This test followed the earlier Lumo experiments but used the new and expanded
Memory Bank as the only supplied project-context source.

## Language Behaviour

The output was largely written in Swedish.

This appears to be related to the Memory Bank’s instruction that direct
communication with Psycedelic should normally be in Swedish.

However, repository-facing documents should normally be written in English.

The test therefore reveals a possible ambiguity between:

- language for direct conversation
- language for generated repository documents

A future Memory Bank revision should state more explicitly:

> Use Swedish for direct conversation with Psycedelic. Use English for all
> repository-facing documents, Markdown mockups, architecture documents,
> case-study material, and generated file content unless Psycedelic explicitly
> requests another language.

---

## Markdown Behaviour

The output demonstrated incomplete Markdown compliance.

Observed problems included:

- malformed YAML headings
- missing separation between labels and code blocks
- mixed Swedish and English inside repository content
- inconsistent formatting
- sections that appeared to be Markdown but were not correctly fenced
- terminology placed directly after labels such as `yaml`

This indicates that:

> Semantic continuity was stronger than format continuity.

The model appeared to understand the project and its architecture better than it
followed the exact Markdown delivery rules.

---

## Workflow Behaviour

The test did not reproduce the exact timing of the earlier test runs.

The user’s second question included both:

- a request to discuss the idea
- a request to create a Markdown mockup

Lumo interpreted this as permission to discuss and create the mockup immediately.

This is not necessarily a failure.

It demonstrates that the instruction was ambiguous enough to support multiple
interpretations.

For a future controlled comparison, use:

~~~~text
Discuss the idea only.

Do not create the Markdown mockup yet.

Wait for my next message before producing the document.
~~~~

The deviation should be recorded rather than hidden.

## Main Findings

### Finding 1 — Consolidation appears useful

One new Memory Bank transferred several kinds of context that previously existed
in separate files.

### Finding 2 — Freeze State concepts were legible

Lumo appeared to understand status, authority, proposal, and human-review
relationships from the consolidated file.

### Finding 3 — Conceptual continuity was strong

The model connected the camera concept to the wider trust architecture instead of
treating it as an isolated feature.

### Finding 4 — Provenance improved

The model explicitly marked the document as proposed and requiring human review.

### Finding 5 — Provenance enforcement remains incomplete

The model still made many new architectural assertions without classifying each
claim individually.

### Finding 6 — Semantic continuity exceeded format continuity

The model understood the project better than it followed all Markdown and
language instructions.

### Finding 7 — The test protocol needs stricter wording

The instruction to discuss and create a mockup allowed the model to create the
document earlier than in previous runs.

## Recommended Follow-Up

The next follow-up test should isolate format behaviour.

Use the same new Memory Bank but add one precise task instruction:

~~~~text
Discuss the idea only.

Do not create a document yet.

Wait for the next question.

When you later create the repository document, write it entirely in English
and place all Markdown content inside one fenced code block.

Do not use triple-backtick fences inside that outer code block.
Use four-tilde fences for internal examples.
~~~~

This should be documented as a separate test rather than silently merged into
Test Run 04.

~~~~text
Test Run 05 — Freeze State with Explicit Format Control
~~~~
